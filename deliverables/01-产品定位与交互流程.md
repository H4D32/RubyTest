# 交付一：产品定位 + 交互流程 + 成立逻辑

**产品名：**《我的AI小岛》  
**命题对齐：** 玩家用语言与操作实时重塑世界，世界随之演化；回访痕迹对得上才可信。  
**技术前提（题目给定）：** 交互式视觉模型（文本/图像指令实时生成 + 对生成结果持续编辑）+ 通用游戏引擎可做原型 + 有玩家可测。

---

## 一、一句话产品定义

> 面向愿意「亲手改世界」的模拟经营玩家的 AI 塑世小岛——通过 **「材料与已有世界状态约束的生成编辑 + 写入后永久生效的世界状态 + 世界对改动的可见演化」**，解决「AI 生成世界缺乏一致性与可信度：玩家回访发现痕迹对不上就停玩」的核心痛点，让每一次塑造都被世界记住，并推动小岛持续演变。

---

## 二、核心问题界定

> 玩家在 **塑造世界并回访检验** 的过程中，因 **AI 实时生成的世界缺少持久状态与前后一致**，导致 **回访时创造物消失/变样、场景痕迹对不上，沉浸崩塌并直接停玩**。现有方案要么只有预设内容（可信但不可塑），要么只有一次性生成（自由但不可信），未能同时满足「自由塑造」与「世界可信」。

**题眼对齐：**  
核心问题不是「玩家能不能用 AI 生成东西」，而是「**塑造写入世界之后，回访时痕迹还对不对得上；世界有没有因此演化**」。  
能生成 ≠ 好玩。先给期待、回访再失望，比没有生成更糟。

---

## 三、问题推导（成立逻辑）

### 3.1 题目线索 → 产品判断

| # | 题目线索 | 产品侧判断 |
|---|---|---|
| 1 | 传统游戏内容由美术预设，玩家无法真正改变世界 | 入口需求：玩家要能用语言/操作实时重塑世界，而不只是消费预设 |
| 2 | 交互式视觉模型支持指令生成与持续编辑 | 技术可行：塑世的主能力应落在「生成 + 继续编辑」，而不是纯对话或纯摆放 |
| 3 | 玩家用回访判断世界是否可信；痕迹对不上就停玩 | 胜负手：持久写入 + 回访一致性；这是玩法成立的硬条件，不是锦上添花 |

### 3.2 因果链

```
传统世界不可塑
    → 玩家要「能改的世界」
交互视觉模型解决「能不能生成/编辑」
    → 但无状态生成容易「这次好看、下次对不上」
玩家回访检验痕迹
    → 对不上 → 出戏 → 停玩
结论：自由塑造是入口；世界状态持久化 + 回访一致 + 可见演化才是玩法能否成立的胜负手
```

### 3.3 需求成立的判断依据

| 维度 | 判断逻辑 | 可验证标准（估算，上线前需玩家验证校准） |
|---|---|---|
| **痛点强度** | 回访是塑世玩法的自然检验行为；不一致直接导致停玩 | ≥60% 目标玩家表示「我改过的场景回访对不上会停玩」；人均日回访 ≥1 次 |
| **现有方案缺口** | 预设世界一致但不可塑；纯生成实验可塑但不记得 | 竞品/实验局中「回访不一致」为主要差评之一，且 7 日留存明显偏低 |
| **解法可行性** | 给定模型可生成+持续编辑；引擎可持久化场景图；可用已有世界状态约束生成 | 写入成功率 ≥90%；回访视觉/语义一致率 ≥95%；单次生成/编辑可玩延迟 ≤5s（可接受上限 ≤10s） |

### 3.4 反证条件（什么情况下本定位不成立）

- 目标玩家对「亲手改世界」的需求不足（多数人更想消费精品预设）→ 入口需求不成立  
- 现有生成玩法已能做到高回访一致性与可接受留存 → 缺口不成立  
- 生成/编辑延迟长期无法压到可玩范围，或无法把结果稳定写入世界 → 技术路径不成立

## 四、目标用户与核心场景

### 4.1 用户

| 分层 | 特征 | 优先级 |
|---|---|---|
| 塑世型模拟经营玩家 | 玩过动森/星露谷等；愿意花时间改造家园；会回访自己的改动 | P0 |
| 创造/装扮型玩家 | 追求「我的岛和别人不一样」；接受用自然语言创造 | P0 |
| AI 尝鲜者 | 好奇新交互，适合早期验证与口碑 | P1 |

### 4.2 核心场景（对应题目闭环）

**场景 A：实时塑世（主场景）**  
玩家用一句话/一张参考图/点选操作，改小岛上的一处场景（不只是摆道具：岸线、空地、小屋外观、地块陈设等）→ 预览 → 确认写入 → 立刻在岛上看到结果。

**场景 B：世界响应与演化（题目「随之演化」）**  
写入后，世界不是静止存档：环境与 NPC 对改动做出可见响应（如新灯点亮夜晚路径、新码头改变访客落点、改过的空地长出可采集物）。演化规则可解释、可回放，避免「随机乱变」。

**场景 C：回访检验（题眼场景）**  
再次登录回到改过的地点：布局、外观、关键物体仍在；允许的演化有记录可查。对不上则沉浸崩塌——产品必须把这条路径做成默认体验，而不是事后补丁。

## 五、产品边界

### 做什么

- 小岛范围内的 **场景塑造**：文本/图像指令生成 + 对结果持续编辑  
- **材料与世界状态约束**：用玩家已有材料/邻近地块风格约束生成，降低「生成很炫但和岛对不上」  
- **确认后写入** 的世界状态持久化（场景图 + 资产引用 + 演化事件日志）  
- **有限、可解释的世界演化**（基于写入结果触发，而非无约束全图重生）  
- 轻量经营循环作为回访动机（采集/交易/装扮），服务塑世，不喧宾夺主  
- NPC 记忆作为「世界记得我」的增强（对话/交易记录），视觉塑世仍是主链路  

### 不做什么（控制一致性风险）

- 不做战斗向 RPG  
- 初期不做实时多人同岛同写（避免并发一致性爆炸）  
- 不做玩家间自由交易市场  
- 不做无边界大世界开放生成（锁定小岛，降低状态复杂度）  
- 不做无约束的全岛一键重生成（禁止「整岛重骰」导致痕迹整体错乱）

## 六、交互流程：玩家塑造 ↔ 世界响应

设计原则：  
1. **自动能做的尽量自动**（解析意图、检索约束、生成候选、写日志）  
2. **改写世界之前必须有玩家确认**（避免「模型擅自改了我的岛」——这和「痕迹对不上」一样致命）  
3. **演化要可感知、可追溯**，不能静默覆盖玩家已确认的痕迹  

### 6.1 端到端主流程

```
[1] 意图输入（玩家）
    语言 / 参考图 / 点选地块与操作
        ↓
[2] 意图理解与约束装配（系统自动）
    解析目标地块、改动类型；装配材料库存、邻接风格、已有场景图
        ↓
[3] 生成 / 编辑候选（系统自动）
    调用交互视觉模型；产出 1–3 个预览；绑定「将影响的地块与物体」
        ↓
[4] 预览比对（玩家确认 · 硬门禁）
    看效果；可「换一批 / 继续编辑指令 / 取消」
    ※ 未确认不得写入正式世界
        ↓
[5] 写入世界（系统自动，确认后）
    更新场景图；固化资产；记录「塑造事件」；扣除材料（若有）
        ↓
[6] 世界响应 / 演化（系统自动 + 可配置）
    触发可见反馈（环境/NPC/玩法单元）；写入「演化事件」日志
        ↓
[7] 当场验收（玩家可选介入）
    满意 → 继续玩；不满意 → 进入撤销/再编辑
        ↓
[8] 回访检验（玩家行为 · 产品必须保证）
    再次进入地块：痕迹一致；演化有记录；异常则进入修复路径
```

### 6.2 系统自动 vs 玩家确认/介入

| 步骤 | 动作 | 责任方 | 说明 |
|---|---|---|---|
| 选地块 / 下指令 / 传参考图 | 表达塑造意图 | **玩家** | 塑世入口 |
| 意图解析、约束装配 | 理解改什么、用什么约束 | **系统自动** | 玩家可不打标签；系统从地块与库存推断 |
| 生成多候选 / 应用编辑 | 视觉生成与持续编辑 | **系统自动** | 使用题目给定的交互视觉模型能力 |
| 预览是否写入世界 | 接受 / 换候选 / 再编辑 / 取消 | **玩家确认（必须）** | 防止擅自改写；这是信任门禁 |
| 写入场景图与事件日志 | 持久化 | **系统自动** | 确认后的唯一真源 |
| 触发演化 | 灯光、路径、访客、可采集物等 | **系统自动** | 规则表驱动；不覆盖玩家已锁定外观，除非再次确认 |
| 演化强度 / 是否允许自动演化 | 偏好设置 | **玩家可选介入** | 默认开「轻度演化」；可改为仅手动 |
| 撤销到上一塑造点 | 回滚 | **玩家介入** | 回访或当场发现不对时的安全网 |
| 标记「异常不一致」 | 反馈 | **玩家介入** | 用于评测与修复；系统可尝试从事件日志重建 |

### 6.3 一条典型演示脚本（供交付二对齐）

1. 玩家点选岸边空地，输入：「修一个木质小码头，傍晚要有灯」  
2. 系统自动带上：木料库存、邻接沙滩风格、当前时间天气预设  
3. 系统给出 2 个预览码头  
4. **玩家确认**其一并写入  
5. 世界响应：日落时码头灯自动亮起；有 NPC 次日从码头登岛（演化可见）  
6. 退出再进：码头仍在、灯的位置仍在；事件日志可查看「因码头写入触发访客点」  
7. 玩家再说：「灯改成玻璃风灯」→ 对已有结果持续编辑 → **再次确认**后覆盖灯光资产，码头主体不变

## 七、定位何以成立（收束）

1. **对准题眼：** 把「回访痕迹一致」写成玩法成立条件，而不是生成效果的附属指标。  
2. **对准能力：** 主交互落在文本/图像驱动的生成与持续编辑，匹配交互式视觉模型，而非另起对话 RPG。  
3. **对准「塑造 + 演化」：** 确认写入解决「记得住」；规则化世界响应解决「随之演化」，且演化不得静默破坏已确认痕迹。  
4. **可证伪：** 痛点、缺口、延迟与一致率均有反证条件；不成立就停投。  
5. **边界克制：** 锁小岛、禁整岛重骰、初期单人，是为了把一致性做硬，而不是功能堆砌。
